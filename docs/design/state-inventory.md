## Visual baseline coverage

`scripts/ui_screenshots.py` captures current browser-rendered routes at 375, 768, and 1440 CSS px in both themes. It uses a throwaway SQLite database and a local mock-mode server. Public, signed-in, and admin paths are explicit. The script records redirects/statuses in `manifest.json` so a screenshot of the wrong page cannot silently pass. It avoids scan payloads, personal data, and the one-time API-key reveal.

Phase 0 cannot honestly show every future loading, error, or content state: `?__state=` does not exist yet, a scanner result needs controlled reputation fixtures, and a browser cannot reproducibly force a backend failure without instrumentation. Later phases should add mock-only fixtures and attach paired before/after screenshots for each changed state. The switch must have no effect when `MOCK_MODE` is false.
