# Phase 2 authentication protocol notes

Checked 2026-11-14 against [Google's ID token verification guide](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token), [Google's HTML API reference](https://developers.google.com/identity/gsi/web/reference/html-reference), [Google's JavaScript API reference](https://developers.google.com/identity/gsi/web/reference/js-reference), and the [PyJWT API reference](https://pyjwt.readthedocs.io/en/stable/api.html).

- Google Identity Services posts `g_csrf_token` in a cookie and form field. The server compares both before verifying the token. A server-issued random nonce is embedded in each Google button/One Tap configuration, stored only as a hash in SQLite, bound to an `HttpOnly`, `Secure`, `SameSite=None`, `__Host-` cookie, and consumed with one atomic `DELETE` after signature verification. The cookie uses `SameSite=None` because Google's redirect callback is a cross-site POST. Challenges expire after ten minutes, and the store retains at most 10,000 active challenges; an old or displaced login page must be refreshed.
- Auth0 ID tokens use PyJWT 2.15.1 for RS256 signature and `iss`, `aud`, `exp`, `iat`, optional `nbf`, and required `sub` checks. The code accepts only a JWT type header and the configured Auth0 issuer/client IDs. The tenant JWKS is fetched at most once per five minutes, including for unknown `kid` values, and the verifier fails closed if a fetch is unavailable. A newly rotated signing key can therefore take up to five minutes to become accepted.
- The mobile compatibility route reads an untrusted issuer hint from the token only to choose the Google or Auth0 verifier. It never uses that hint as proof of identity; the chosen verifier must validate the signature and claims before an account lookup.
- The mobile `/auth/verify` response shape is unchanged. Provider-account mapping is handled by the Phase 2 identity code in this branch.

The Google callback's `g_csrf_token` and browser nonce checks must be verified on `sqafe.com` in a real browser before deployment. Public HTML currently advertises `https://sqafe.com/auth/google` as the callback. Anonymous login pages opened on the alternate Render hostname redirect to the configured canonical host before a nonce is issued, so the host-only nonce cookie reaches the callback. Verify this redirect and the Google Console authorized origin/redirect settings during release preflight.
